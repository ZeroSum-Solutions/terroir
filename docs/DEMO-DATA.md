## Teardown (copy-paste this ONE statement)

```sql
delete from public.restaurants
  where id = 'de000000-0000-4000-8000-000000000001';
```

That single DELETE cascades through every child table (memberships,
wines, inventory_items, open_bottles, pour_events,
availability_events, wine_lists → wine_list_sections →
wine_list_items). ~280 rows gone, no orphans.

You can run it via:
- the Supabase Dashboard SQL editor, OR
- the Supabase MCP (`execute_sql` on project `qcfmwphlaekfkqwkfyth`),
  OR
- `psql` against the prod DB with service-role credentials

**If you want just specific pieces gone** (e.g., keep the restaurant
but drop the wine list), the UUID prefix pattern above makes it easy
to target exactly what you want.

## Sanity query (before teardown)

Confirms what's in the demo scope:

```sql
select
  r.name,
  (select count(*) from public.wines w where w.restaurant_id = r.id) as wines,
  (select count(*) from public.wine_lists wl where wl.restaurant_id = r.id) as lists,
  (select count(*) from public.inventory_items ii where ii.restaurant_id = r.id) as inventory,
  (select count(*) from public.open_bottles ob where ob.restaurant_id = r.id) as open_bottles,
  (select count(*) from public.pour_events pe where pe.restaurant_id = r.id) as pour_events
from public.restaurants r
where r.id = 'de000000-0000-4000-8000-000000000001';
```

rows · 11 open bottles · 30 pour events.
