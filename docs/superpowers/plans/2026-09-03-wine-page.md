# Wine Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild `/cellar/[wineId]` so a wine reads with a house taste block, a dual score, a sourced drinking window, operational badges and a vintage rail — and reuse those blocks in condensed form on the bottle-scan result card.

**Architecture:** Phase 1 ships a working tasting log — a `wine_notes` corpus with a controlled descriptor vocabulary, captured on the page, plus the writer change that makes the later retirement possible. Phase 2 adds three composable server resolvers that return provenance-carrying `Sourced<T>` values, five display blocks that render their own honesty labels from that basis, and the flagged worker job that retires the invented `claude_inference` values.

**Tech Stack:** Next.js 16 App Router server components, Supabase Postgres + RLS, TypeScript, Vitest, Tailwind against the Nocturne tokens in `DESIGN.md`.

**Spec:** `docs/superpowers/specs/2026-09-03-wine-page-design.md` — read it before Task 1. The plan argues from the spec; the decision table (§2) explains every choice below.

## Global Constraints

- **`.env.local` holds production credentials.** Never point a test, script or migration at it. Start the dev server with `scripts/local/dev-local.sh`, never bare `pnpm dev`.
- **`src/types/database.ts` is generated.** Never hand-edit. `pnpm types:gen` after any migration.
- **Migrations are forward-numbered from 0148 with paired downs** at `supabase/migrations/down/NNNN_<name>.down.sql`; the basename must match exactly or `pnpm run downs:check` fails. Read `docs/runbooks/migration-numbering.md` before picking a number on a branch.
- **Every migration numbered 0112 or higher needs a row in the normative manifest** at
  `docs/plans/2026-08-24-visual-wine-platform-spec-list.md` §1, and `pnpm run manifest:check` fails
  without one. The manifest's own rule is that changes land in that document *first*. This applies
  to Tasks 2, 4, 8 and 19 — every task in this plan that adds a migration.
- **Merging to `main` deploys; migrations do not ride along.** Every migration must be safe against a database the old code is still talking to.
- **Never hand-edit `docs/feature-ledger.json`.** Change it through its generator and run `pnpm verify:feature-ledger`.
- **Never commit to `main`.** One feature = one branch = one squashed commit.
- **Service-role calls bypass RLS entirely.** Every service-role call site gates on membership first and passes only the session's own `restaurantId` into subsequent `.eq("restaurant_id", …)` filters.
- **Ratchets fail on growth:** `pnpm check:file-size` (400 lines source / 1000 test) and `pnpm check:control-rows`. Pay debt down with `pnpm check:file-size:update` after a split — never raise a baseline to make a gate pass.
- **Palette:** `pnpm check:design` reads every colour literal in `src/`. No warm hue (15–60°) at `L < 0.72` (brown) or `L ≥ 0.80` (cream). No fifth hue beyond the four wine states.
- **Gate command set** run before anything lands: `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm test`, `pnpm check:design`, `pnpm check:file-size`, `pnpm check:control-rows`, `pnpm eval:vwp`, `pnpm verify:feature-ledger`, `pnpm verify:api-contract`, `pnpm verify:product-conformance`, `pnpm run snapshot:check`, `pnpm run types:check:local`, `pnpm run downs:check`, `pnpm run manifest:check`.

## How to read the acceptance evidence blocks

Every task ends with **Acceptance evidence** — the binary bar a reviewer judges against. "Tests pass" is never evidence on its own. The block names the artefact to inspect and the observation that constitutes a pass, so a critic with fresh context can reach the same verdict without re-deriving the task.

- [ ] **Step 1: Write the migration, with a header in the house style**

Follow `0136_wine_ownership_on_write_policies.sql` — it documents the defect, the reasoning, and
what was measured before applying. That prose is the convention, not decoration.

```sql
-- 0148_wine_notes.sql
--
-- The house tasting-note corpus, its controlled descriptor vocabulary, the
-- global sourced-reference table, and the drink-window provenance columns.
--
-- WHY THE RLS IS NOT MEMBERSHIP-ONLY
-- wine_notes.wine_id is `references public.wines(id) on delete cascade`, and
-- Postgres FK cascades run as the table owner and BYPASS RLS. A membership-only
-- WITH CHECK is exactly the hole 0136 had to close on stock_adjustments and
-- bottle_closeouts: tenant B files a policy-compliant row naming tenant A's
-- wine, and tenant A's ordinary delete silently destroys it. The `exists`
-- clause below reads public.wines under the CALLER's rights, so a foreign
-- wine_id is rejected twice over — by the explicit equality and by the caller
-- not being able to see the row at all.
--
-- WHY wine_reference_notes HAS NO restaurant_id
-- It is published reference data, ingested from producer and importer sheets,
-- not tenant-authored. lwin_catalog and xwines_catalog carry no tenancy column
-- either, and canonical_wines is global. One fetch serves every restaurant
-- holding that wine. There is deliberately NO tenant INSERT policy: the only
-- writer is the service-role ingestion job.
--
-- WHY vintage IS NOT NULL ON wine_reference_notes
-- Producer sheets, importer books and retailer scores are vintage-specific. A
-- vintage-less row would attach a 2015 retailer score to a 2019 bottle,
-- globally, with a source URL beside it — worse than an unsourced guess,
-- because the UI would be claiming provenance for it.

create table public.wine_notes (
  id               uuid primary key default gen_random_uuid(),
  restaurant_id    uuid not null references public.restaurants(id) on delete cascade,
  wine_id          uuid not null references public.wines(id) on delete cascade,
  author_user_id   uuid not null references auth.users(id),
  body             text not null check (length(btrim(body)) > 0),
  score            smallint check (score between 50 and 100),
  tasted_on        date,
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now()
);

create index wine_notes_wine_idx on public.wine_notes (wine_id, created_at desc);

alter table public.wine_notes enable row level security;

create policy "members read own wine_notes" on public.wine_notes
  for select using (restaurant_id in (select public.member_restaurant_ids()));

create policy "members insert own wine_notes" on public.wine_notes
  for insert with check (
    restaurant_id in (select public.member_restaurant_ids())
    and author_user_id = auth.uid()
    and exists (
      select 1 from public.wines w
      where w.id = wine_notes.wine_id
        and w.restaurant_id = wine_notes.restaurant_id
    )
  );

create policy "authors update own wine_notes" on public.wine_notes
  for update using (author_user_id = auth.uid())
  with check (
    author_user_id = auth.uid()
    and exists (
      select 1 from public.wines w
      where w.id = wine_notes.wine_id
        and w.restaurant_id = wine_notes.restaurant_id
    )
  );

create policy "authors and owners delete wine_notes" on public.wine_notes
  for delete using (
    author_user_id = auth.uid()
    or restaurant_id in (select public.member_restaurant_ids_with_role('owner'))
  );

comment on table public.wine_notes is
  'House tasting notes. INSERT requires membership of the row''s restaurant, self-attribution, AND that wine_id belongs to that same restaurant (0148, following 0136) — wine_id cascades on delete and cascades bypass RLS.';

-- === the controlled vocabulary ===

create table public.descriptors (
  slug   text primary key,
  label  text not null,
  family text not null,
  sort   int  not null default 0
);

alter table public.descriptors enable row level security;
create policy "authenticated read descriptors" on public.descriptors
  for select to authenticated using (true);

create table public.wine_note_descriptors (
  note_id         uuid not null references public.wine_notes(id) on delete cascade,
  descriptor_slug text not null references public.descriptors(slug),
  origin          text not null check (origin in ('confirmed','inferred')),
  primary key (note_id, descriptor_slug)
);

-- The composite primary key is load-bearing, not hygiene: promotion from
-- 'inferred' to 'confirmed' is an UPDATE of origin, and without this key an
-- insert-based promotion would double-count the descriptor in every tally.

alter table public.wine_note_descriptors enable row level security;

create policy "members read own note descriptors" on public.wine_note_descriptors
  for select using (
    exists (
      select 1 from public.wine_notes n
      where n.id = wine_note_descriptors.note_id
        and n.restaurant_id in (select public.member_restaurant_ids())
    )
  );

create policy "authors write own note descriptors" on public.wine_note_descriptors
  for all using (
    exists (
      select 1 from public.wine_notes n
      where n.id = wine_note_descriptors.note_id
        and n.author_user_id = auth.uid()
    )
  ) with check (
    exists (
      select 1 from public.wine_notes n
      where n.id = wine_note_descriptors.note_id
        and n.author_user_id = auth.uid()
    )
  );

-- === global sourced reference notes ===

create table public.wine_reference_notes (
  id                  uuid primary key default gen_random_uuid(),
  canonical_wine_id   uuid not null references public.canonical_wines(id) on delete cascade,
  vintage             int  not null,
  source_kind         text not null check (source_kind in ('producer','importer','retailer')),
  source_name         text not null,
  source_url          text not null,
  fetched_at          timestamptz not null,
  body                text,
  score               numeric,
  score_scale         smallint check (score_scale in (5, 100)),
  drink_window_start  int,
  drink_window_end    int,
  unique (canonical_wine_id, vintage, source_kind, source_name)
);

alter table public.wine_reference_notes enable row level security;
create policy "authenticated read reference notes" on public.wine_reference_notes
  for select to authenticated using (true);
-- No INSERT/UPDATE/DELETE policy, deliberately. The service-role ingestion job
-- is the only writer; authenticated users must never be able to author a row
-- that every other tenant will read as sourced fact.

-- === drink-window provenance ===

alter table public.wines
  add column drink_window_basis  text check (drink_window_basis in ('sourced','override','inferred')),
  add column drink_window_set_by uuid references auth.users(id),
  add column drink_window_set_at timestamptz;

comment on column public.wines.drink_window_basis is
  '0148 — where this window came from. Backfilled to ''inferred'' where rating_source = ''claude_inference'' and to ''override'' where manual_overrides contains ''drink_window''. The enrichment selector keys on this being null so a deliberately retired wine is not mistaken for an un-enriched one.';

update public.wines
   set drink_window_basis = 'override'
 where 'drink_window' = any(manual_overrides);

update public.wines
   set drink_window_basis = 'inferred'
 where drink_window_basis is null
   and rating_source = 'claude_inference'
   and drink_window_start is not null;
```

The backfill is additive — it writes a new column and touches no existing value — so it is safe
against a database the old code is still talking to.

### Task 17: ~~The rating ramp in `DESIGN.md`~~ — CUT

**Cut 2026-09-03 (spec D16). No files change.**

The ramp was built and measured before it was cut, so the evidence is on the record rather than
asserted: five steps, low achromatic to high claret, every ink/wash pair clearing 4.5:1 in both
rooms with margin (7.12:1 to 16.13:1), and every step passing the brown/cream gate because claret
sits at hue ~350, outside the 15–60° wedge that gate polices. It would have shipped.

It is cut because the design contract forbids it, on three of its own rules:

1. **"There is no `info` hue and there must not be one... A fifth colour would dilute the thesis
   to buy nothing."** A rating→warmth scale is an information hue.
2. **"Photography carries the warmth so no surface has to."** Tinting a numeral puts warmth on a
   surface.
3. **"At peak" is achromatic** *because* the good, quiet, common state "should not compete for
   attention with the two states that need action." Giving a high score the one claret makes a
   98-point wine compete with Window risk — same hue, valence inverted.

A score renders in ordinary ink with its provenance sentence beside it. The numeral and its
source already carry the whole claim; the colour would have carried nothing the text did not.

**Acceptance evidence.** `git diff DESIGN.md` and `git diff src/app/globals.css` are both empty
for this task, and no `--t-rating-*` token exists anywhere in the repo. `pnpm check:design`
passes, as it did before — this task adds no colour to the system.
